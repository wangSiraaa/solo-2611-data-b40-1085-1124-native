# 以旧换新·旧打字机拆件回收（合成口径）

> 本子系统与仓库原有的集团合并工作底稿（`group_consol/`）**相互独立**：它们是两道
> 不同的题。这里只实现题目给出的合成口径，不实现现实会计准则、回收法规或税务制度。

场景：两家门店合营一场打字机以旧换新。验收台把“已开单”这件事落到可核对账头与
交接件上；回收工场在“三机 / 六工单 / 八格班时”上限内把旧机拆成字杆包（或整机 /
整副字篮）交付回收商；改单/预约状态机决定预接件单何时能换成整机单、预约何时占位
与释放，并**显式交出**“留唯一待单位 vs 先开工”的可交结果差异。

## 目录

| 路径 | 职责 |
| --- | --- |
| `tradein/acceptance.py` | 验收台：发票对齐+真实外销、换购小票、钥匙存放、整单退机、应收挂账/结清、入库门槛、逐机可回收判定、跨卖场双重认领拒绝 |
| `tradein/diagram.py` | 实机分解图：格/件/字篮/复装、阶段顺序、相邻杆损伤、工位与格班时、不可逆判定 |
| `tradein/workshop.py` | 工场求解器：枚举终止方案 + 订单二分匹配，最大化兑现数、平手最少工时 |
| `tradein/convert.py` | 改单/预约状态机：在途改整机、窗口保护、预约占位/释放、签回改单、代价对比 |
| `tradein/audit.py` | 甲机三视图交叉断言 |
| `scripts/run_tradein.py` | 端到端演示（打印结构化结果） |
| `tests/test_tradein.py` | 30 个单元测试，覆盖每条要求 |

运行：

```bash
python3 scripts/run_tradein.py
python3 -m unittest tests.test_tradein -v
```

## 1. 验收台（acceptance.py）

### 账头：发票对齐 + 真实外销 + 小票守恒
- `align_invoice` 登记一张**已对齐**的内部发票（seller/buyer/q/T/C），作为新机来源。
- `open_external_sale` 在**真实卖场**开对外售价单，初始 `status=receivable`（先挂应收）；
  `settle_external_sale` 凭收款凭证逐笔结清，累计不超限，结满转 `settled`。
- `record_ticket` 记换购小票：`cash + Σ trade_values == 对外售价`，逐项列示且与
  所列旧机一一对应；一票最多两台具名旧机。**不守恒整票拒绝**。

### 交接件：钥匙、存放、整单退机、入库门槛
- 未交钥匙 (`key_handed_in=False`) 时 `stored=True`、`can_be_dismantled()=False`——
  柜方无权拆。
- `cancel_ticket` 为**结算前反悔**：整单撤销（现金+折价+旧机全退），外销单同步
  `cancelled`。已交付且已入账后反悔不再按“结算前”处理（保守拒绝）。
- `admit_to_inventory` 只在 `inventory_unlocked()`（新机已交付 **且** 约定现金已入账
  **且** 未撤销）时放行——这是“才成馆方存货”的硬门槛。

### 逐机判定 + 双重认领
- `recoverable_bodies()` 对每台机独立给出 `bookable`（折价已兑现且可入账）、
  `physical`（钥匙已交、可拆）、`realized_value`（已兑现折价）、`recoverable`。
- `register_machine` 以 `body_id` 全局唯一：**两处卖场同时认领同一机身**直接
  `ClaimError`。

## 2. 实机分解图（diagram.py）

- **阶段依序**：螺帽(0) → 压条/固定杆(1) → 字杆(2)。拆某件前须先拆完更低阶段；
  同阶段内顺序自由（甲机先 Y 后 X 的空间）。
- **相邻杆损伤**：拆件时按 `Piece.damage` 损掉登记的相邻字杆；若目标杆已先被取走，
  损伤落空（所以“先取 Y 不伤 X，先取 X 会损 Y”）。
- **整副字篮**：`apply_take_basket` 保住篮内全部杆，但从此只能作为**一整副字篮**交，
  不得再当散杆取。
- **可复装**：`Piece.reversible` 的操作复装占 `reassemble_cells` 格班时，已花班时照计；
  有**不可复装**件被拆、或有散杆/字篮已发出时，`apply_deliver_whole` 拒绝追认整机。
- **工位与格班时**：每拆一件占 `Piece.cells` 格、一个工位（容量由调用方约束）。

## 3. 工场求解器（workshop.py）

严格字典序目标：**① 能完整兑现的订单数最大 → ② 总工时（格班时）最少**。

- 每台机枚举全部**非支配终止方案**（任意时刻停 / 整机交 / 拆篮后停），同状态取最低工时。
- 跨机组合后，把各机产出实物与订单做**最大二分匹配**（增广路）。
- 订单是**具名机型 + 键位 / 完整字篮 / 整机**；`Item.matches` 逐字校验，不兼容的杆
  不可顶。
- 同一台机不能既交整机又交散杆（整机方案一旦交付即封死拆取）。
- 规模硬上限：最多 3 机、6 单；预算默认 8 格。超出上限构造即 `ValueError`。

输出 `SolveResult.as_json()`：`fulfilled_count / total_cells / assignments`（每单的
真实领机、交付实物、拆取次序 `claim_steps`）/ `unfulfilled / plans`（每台机的拆取
次序与包内件）。

## 4. 改单/预约（convert.py）

### 首次不可逆拆取前的整机改单
`try_convert_to_whole` 依次检查：
1. 已发生**首次不可逆拆取** → 拒，并把旧的“整机可交”`Quote` **失效**（`valid=False`）。
2. 已发出散杆/字篮、或已拆坏实物 → 拒（已发走或拆坏的实物不能追认整机）。
3. 仅可复装操作 → **允许**改；复装另占格班时，已花班时照计。
4. **其余已接件单仍须都能交**：用 `Workshop` 对剩余订单复核可行性，不通过则拒。

### 窗口、预约、签回
- `SlotPool`：稀缺的工位待单位（默认容量 1）。`issue_reservation` 占位；
  `release_reservation` 归还；重复占用 `ReservationReuseError`。
- `station_guard`：改整机窗开 **且** 预约占位 **且** 未释放、未收到释放时，工位
  **不得做不可逆拆取**（可复装操作不受限）；窗关闭或收到释放后放行。
- `convert_via_signed_back`（POLICY_DEMAND）：工位先开工，柜台须等 `sign_back()`
  按现场零件状态签回后才能受理改单；未签回即拒。

### 在途测试（题目指定同一在途请求）
- A：只松螺帽（可复装）→ **可改**。
- B：固定杆已剪断（不可逆）→ **拒绝**，且旧的“整机可交”报价 **失效**。
- 两视图用相同初始机、相同订单、相同总预算（`budget=8`）。

### 两种做法的代价（题目要求“明确这份代价”）
`compare_policies(reservation_window_end, third_machine_deadline,
customer_convert_deadline)`，其中第三机截止 `<` 窗结束：
- **POLICY_ALWAYS（留唯一待单位）**：预约占住到窗结束，第三机在截止前无法开工 →
  第三机订单**落空**；但整机改单**保证**成功。
- **POLICY_DEMAND（先开工）**：第三机按期交付；改整机须等签回，顾客期限若早于签回
  时点则**不保证**、按原单继续。
查询方式：`compare_policies(...)` 返回两条 `PolicyOutcome`，字段
`conversion_guaranteed / third_machine_met / notes` 直接说明“可交结果差异”与代价。

## 5. 甲机三视图（audit.py）

甲机有 X、Y 各一杆；取 X 损 Y，先取 Y 不伤 X；两单各收一杆；已有两格工时且钥匙已交
结清。`audit_jia_machine(already_spent=2, budget=8)` 断言：
1. **原头**：先 Y 后 X，**两单都能交**（`fulfilled_count=2`）。
2. 仅把**账头退至换购现金到账前**（实物不变）→ 未成馆方存货、不可回收，
   **两单都不能交**（`fulfilled_count=0`）。
3. 恢复原头，只把**压条检验**改为“取任一杆也损另一杆”（`mutual_damage=True`）→
   **最多一单**。

## 6. 取舍说明

- **求解方式**：对小规模（≤3 机/≤6 单/≤8 格）做穷举枚举+匹配，换取“最大兑现数、
  平手最少工时”的**可证明最优**与可复现拆取次序；规模增大时需换 ILP/搜索剪枝。
- **损伤/字篮/复装**都是显式登记在分解图上，而非隐含在代码分支，便于逐机审计与
  替换口径。
- **改整机的不可逆性**以“实物是否已无法追认”为唯一标准（有不可复装件、有散杆/字篮
  发出、有损伤）；账头层面的可行性另由“其余订单可交”复核把关，两者分开，避免用
  账面凑平掩盖实物已破坏。
- **代价透明**：预约的稀缺性用 `SlotPool` 显式建模，两种做法的可交差异用
  `compare_policies` 输出，而不是藏在时序里。
