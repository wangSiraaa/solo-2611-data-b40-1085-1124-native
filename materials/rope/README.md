# rope —— 五轴真实位型余捻样本

`input.json` 用**真实 32 位 float32 位型**录入每条纱的累计边界读数（8 位十六进制）。
每轴 ≤ 8 寸，共 5 轴。读数不是用宿主 float 生成的：所有值都经
`obsdelivery.twist.encode_bits` 精确编码，并从 `semantics.decode` 解码回同一个
`Fraction`（测试 `test_encode_bits_roundtrips_exact_values` 复核）。

每轴字段：

* `residuals`：各寸余捻（相邻边界读数之差），精确小整数。
* `cumulative_bits`：各边界点的累计转数位型（`length+1` 个点，段与段共用端点）。

本样本各轴（逐寸余捻）：

| 轴 | 长度 | 余捻（寸 0..） |
|---|---|---|
| J | 8 | `2, −1, 1, 1, 1, 1, 0, 0` |
| Y | 8 | `−2, 1, −1, −1, −1, −1, 0, 0` |
| A | 8 | `0, 1, 1, 0, 0, 0, 0, 0` |
| B | 1 | `−1` |
| C | 1 | `−1` |

J、Y 全长余捻分别为 `+5` 与 `−5`，正好抵消，且**逐寸**相加全为 0（从正头
整段并即平服）。`J[0:2]+Y[0:2]` 与 `J[2:4]+Y[2:4]` 也各为 `0,0`，可分别给
两台裁。注意“全书抵消”并不等于“任意裁段都平服”：甲/乙（`0,2,1` 与
`0,−2,−1`）在把乙中间读数改为 `−1` 后总长仍抵消，逐寸却出现 `1,−1`——
这个反例由 `materials/739` 式的甲/乙场景在 `rope_demo` 中演示。

`python3 -m obsdelivery.rope_demo` 用这份样本跑甲/乙、两处裁台、争寸、
晚到单与实物号审计等全部场景。
